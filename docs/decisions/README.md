# Architecture Decision Records

Create an ADR for a consequential, durable choice such as changing service ownership, introducing a cross-service protocol, selecting persistence/infrastructure, changing compatibility policy, or adopting a security model.

Name records `NNNN-short-title.md`, copy `TEMPLATE.md`, and use one status: `proposed`, `accepted`, `superseded`, or `rejected`. Do not rewrite accepted history; add a new ADR and link the superseded record.

The decision should explain context, constraints, considered options, consequences, compatibility, rollout, and rollback. Link implementation pull requests or issues when available.
